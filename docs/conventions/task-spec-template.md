## Problem Statement

Describe the problem this task solves in 2-4 sentences. Focus on **why** this work is needed, not **how** to implement it. Include:
- What is broken, missing, or inefficient?
- What is the impact if this is not addressed?
- Who is affected (users, developers, the system)?

## Current State

Describe the current implementation or behavior. Include:
- Which files/modules are involved?
- What is the current approach or architecture?
- What are the limitations or issues with the current state?
- What existing patterns or conventions are relevant?

This section helps the agent (or blueprint generator) understand the codebase context before implementation.

## Recommended Approach

Describe the high-level solution strategy. This is **not** detailed implementation steps — those belong in the Implementation Blueprint. Include:
- Which architectural pattern or design to follow
- Which existing conventions or ADRs to reference
- Any trade-offs or alternative approaches considered
- Why this approach was chosen over alternatives

## Implementation Blueprint

*This section is generated by the Blueprint Agent during the gate phase. It provides implementation-level detail that the worker agent executes directly.*

### File Analyses

For each file to be modified or created, the blueprint includes:
- **Current Structure:** Key functions, classes, imports, integration points
- **Integration Points:** Exact line numbers and code references where changes connect
- **Pattern to Follow:** Existing code style, error handling, or architectural patterns in that file

Example:
```
### File: src/worker/prompt-builder.ts (Modify)
**Current Structure:** Exports buildSystemPrompt() and buildTaskPrompt(). CORE_AGENT_INSTRUCTIONS is a large template string at lines 14-68.
**Integration Points:** Insert new section after line 68 (Context Recovery section) but before the closing backtick. Update buildTaskPrompt() at line 150 to insert blueprint content between task spec and repo map.
**Pattern to Follow:** Use `##` markdown headings, numbered lists, and match the existing instructional tone.
```

### Code Examples

Before/after code snippets showing exactly what to change. Example:
```typescript
// BEFORE (lines 67-68):
Update this file after completing each major step.
If you find an existing \`claude-progress.txt\`, read it first to recover your state.`;

// AFTER:
Update this file after completing each major step.
If you find an existing \`claude-progress.txt\`, read it first to recover your state.

## Blueprint Execution

If an **Implementation Blueprint** is included in your task prompt, follow these rules:
1. **The blueprint is your primary guide.**
2. **Do NOT explore or search for integration points** — they are already mapped.
...`;
```

## Verification Patterns

Deterministic checks the agent and judge use to verify completion. Each pattern is a grep-based assertion:

| Criterion | Check | Pattern | File | Expected |
|-----------|-------|---------|------|----------|
| Blueprint section exists | grep | `## Blueprint Execution` | src/worker/prompt-builder.ts | 1 match |
| Primary guide instruction | grep | `blueprint is your primary guide` | src/worker/prompt-builder.ts | 1 match |
| Function signature updated | grep | `blueprint\?: string` | src/dispatcher/dispatcher.ts | 1 match |
| Template file created | file_exists | docs/conventions/task-spec-template.md | - | exists |

The agent should self-check these patterns before calling `verify`. The judge uses them as deterministic pre-checks before LLM evaluation.

## Anti-Patterns

Hard constraints — violations are finishing-sequence blockers, not suggestions:
- Do NOT remove or weaken existing CORE_AGENT_INSTRUCTIONS rules
- Do NOT make blueprint-execution instructions unconditional (must handle no-blueprint case)
- Do NOT change maxTurns in adapter.json (only document recommendation as a comment)
- Do NOT move conventions summary or referenced conventions sections (cache optimization)
- Do NOT include blueprint in retry prompt BEFORE judge feedback (feedback must come first)
